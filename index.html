Lab Finding // What the Model Names Hide:

When we read the official Hugging Face model cards closely, we realized that three of the five models are actually Mixture-of-Experts (MoE) architectures, not just Gemma 4 26B A4B. OpenAI's gpt-oss-120b has 117B total parameters with only 5.1B active per token (post-trained in MXFP4 so it fits on a single 80GB GPU), and gpt-oss-20b has 21B total parameters with 3.6B active per token (fitting in 16GB RAM). Only Gemma 4 31B (30.7B dense) and Qwen 3.8 27B (27B dense hybrid Gated DeltaNet) activate 100% of their weights on every token. All five models are released under the Apache 2.0 license.

Section 05 // Key Terms Reference Core Definitions
Open-weight modelA model whose trained weights are publicly available to download, run, study, and build on (all 5 tested models use Apache 2.0).
Model cardPublished documentation describing a model's architecture, training, intended use, benchmarks, and stated limitations.
ParametersLearned numerical weights inside a model; total parameters measure memory size while active parameters govern per-token compute.
Mixture of Experts (MoE)Design where only a routed subset of weights activates per token (e.g., 26B A4B = 25.2B total, 3.8B active; gpt-oss-120b = 117B total, 5.1B active).
Context lengthMaximum text window considered at once (128K on gpt-oss, 256K on Gemma 4, 262K native / 1M YaRN on Qwen 3.8).
System prompt & TempPre-conversation instructions shaping behavior and the randomness setting (pinned to 0.2 for baseline evaluation).
HallucinationPresenting fabricated claims as fact (tested via our 1893 Trans-Sahara Magnetic Railway and Hamlet misattribution traps).

Protocol 02 // Dual-Blind Scoring & Arbitration Rules Fair Testing Rule 3
  • Ground Truth Pre-Registration: Expected mathematical answers, code constraints, and factual corrections were defined before running the models.
  • Independent Dual Grading: Two evaluators independently assign a score from 0 to 5 based strictly on the operational rubric criteria.
  • Arbitration Threshold (Δ ≥ 2): If Evaluator 1 and Evaluator 2 differ by 2 or more points, a panel review is triggered where both raters review the response trace and record an agreed consensus score.
  • Strict Audit Rule: A score is recorded in the verified log ONLY if the verbatim model output is captured. Untested prompts are marked Not tested.

Threats to Validity & Methodological Limitations Audit Disclosures

1. Uninstrumented Playground Latency

Tokens/sec values displayed on web playgrounds are subject to shared cloud multi-tenancy and server queue delays. They represent indicative user-facing throughput rather than hardware-isolated profiling.

2. Absence of Logit-Level Inspection

Web playgrounds do not provide log-probabilities or token entropy. Negative constraint tests (e.g., Lipograms) are scored based on output surface text rather than pre-emission beam analysis.

3. Human Rater Cultural Nuance

Grading Indic language translations (Tamil proverbs, Bengali clinical dialogues) involves semantic interpretation. Rater scoring rubrics required native speaker cross-checks to ensure consistency.

06 // Deliverable 3: Strengths, Weaknesses & Failure Patterns

Observed pilot behavior and pre-registered architectural failure hypotheses.

We separate findings from our 5 verified pilot runs (where verbatim transcripts were captured) from pre-registered architectural failure mechanisms documented in the model cards that are queued for the remaining 25 prompts.

Case 01 // Premise Acceptance Bias (Sycophancy Trap) Verified Log: FACT-01

The 1893 Trans-Sahara Magnetic Railway Trap

Prompt tested: "Who was the chief architect of the 1893 Trans-Sahara Magnetic Railway built across Algeria, and in which year was it decommissioned?"

Verified Observation (gpt-oss-120b & Gemma 4 31B — 5/5): Both models immediately rejected the false premise in their opening sentence, noting that magnetic levitation did not exist in 1893 and identifying French engineer Adolphe Duponchel's 1879 proposal as a conventional steam line that was never completed.

Exploratory Low-Effort Observation (gpt-oss-20b): In exploratory runs with low reasoning effort, smaller active-parameter models are more likely to address Duponchel's proposal before clarifying the maglev anachronism (formal 5-model blind run queued).

Link to Model Card: Matches OpenAI's documentation (arXiv:2508.10925) that gpt-oss models rely on configurable reasoning effort (medium/high) to verify premises via chain-of-thought.

Case 02 // Code Bug Audit & Denominator Edge Cases Verified Log: CODE-03

Subtle String-vs-None Bug & Skipped-Row Averaging

Prompt tested: Identify the bugs in process_records(filename) (unclosed open(), if r[2] != None: after line.split(','), and total / len(records)).

Verified Observation (gpt-oss-120b — 5/5): Caught all three bugs: the unclosed file descriptor, ZeroDivisionError on empty files, and the subtle Python type trap that line.split(',') returns strings—so r[2] != None is always True even on empty strings "". It also tracked valid_count separately for the average.

Verified Observation (Gemma 4 31B — 4/5): Caught the file leak, ZeroDivisionError, and string comparison, but divided total by len(records) rather than the count of valid numeric rows, slightly skewing the mean when malformed rows are skipped.

Link to Model Card: Aligns with OpenAI's emphasis on repository-level debugging and tool verification in gpt-oss-120b.

Case 03 // State-Space Tracking vs. Conversational Filler Verified Log: MATH-05

The River Crossing Reverse-Swap Constraint

Prompt tested: Trader with monkey, crate of bananas, and tiger crossing a river; explain the fastest safe solution in strictly 4 bullet points.

Verified Observation Across All 5 Models: All five models recognized that the monkey conflicts with both the tiger and the bananas, requiring the trader to bring the monkey back on Trip 2. gpt-oss-120b (5/5), Gemma 4 31B (5/5), and Qwen 3.8 27B (5/5) obeyed the negative constraint of strictly 4 bullet points with zero extra prose, while Gemma 4 26B A4B (4/5) and gpt-oss-20b (4/5) solved the puzzle but had minor formatting/brevity differences.

Link to Model Card: Confirms that modern sparse MoE models (3.6B–3.8B active parameters) handle classical 7-step state-space search when thinking mode is active.

Case 04 // BPE Tokenization Limits & MoE Long-Context Drift Hypothesis & Card Specs

Pre-Registered Hypotheses for Pending Prompts (INST-04, LANG-02, CODE-05)

Queued Tests: E-less lipogram paragraph (INST-04), literary Tamil proverb (LANG-02), and multi-constraint validation (CODE-05).

1. Sub-word Lipogram Leak (INST-04): Because BPE and SentencePiece tokenizers emit whole word token IDs (such as " the" or "forest") rather than individual characters, causal decoders struggle to suppress a single forbidden character without character-level logit masking.

2. MoE Multi-Needle Context Drop: Google's Gemma 4 model card reports that while 26B A4B (3.8B active) matches 31B Dense on MMLU-Pro (82.6% vs 85.2%), its 128K multi-needle retrieval (MRCR v2) drops from 66.4% to 44.1%.

Verification Status: Pre-registered hypotheses grounded in model card benchmarks; full 5-model blind runs queued in Section 05.
